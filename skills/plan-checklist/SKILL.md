# Plan Checklist

作業計画書と、その中のチェックリストだけを作成・編集する。チェックリストに記載した実作業は実行しない。

## 対象

- 作業の目的、範囲、対象外、前提・制約、完了条件、手順を計画書に記録する。
- 具体的なチェック項目を追加・編集し、依頼に応じて完了項目を `[x]` に更新する。
- 実施済みの確認、未完了項目、残課題を計画書に記録する。

## 対象外

計画書・チェックリストの編集以外は行わない。ソースコード、設定、依存関係、テスト、通常のドキュメント本文を変更せず、コマンド、テスト、Lint、ビルド、型チェック、検証を実行しない。外部サービス、認証情報、デプロイ、インフラも操作しない。チェックリスト項目に書かれた作業も代行しない。

ただし、「計画書の推敲」に必要な一時ファイル・検査記録の作成と、`yomiyasu` の検査スクリプトの実行は行ってよい。

## 手順

1. 依頼から目的、対象範囲、対象外、前提・制約、完了条件を整理する。計画対象そのものが特定できない場合は、最小限の確認質問をして編集を待つ。
2. リポジトリ内の既存の計画書、作業メモ、文書配置の慣例を確認する。既存の計画書があればその場所と形式に従う。慣例がなければ `docs/work-plan.md` を使い、`docs` がなければ作成する。
3. 既存の計画書を上書きせず、今回の作業用セクションを追記する。タイトルに作成日時を年月日・時分まで含める（例: `2026-10-13 14:30 作業計画`）。日時は「日時の取得方法」に従って取得する。
4. 作業開始前に、同じ計画書へ目的、対象範囲と対象外、前提・制約、完了条件、依存関係が分かる順の作業手順を記す。
5. 作業手順を同じ文書の「チェックリスト」見出しの下に、実行単位の `- [ ]` 項目として分解する。各項目には対象ファイルまたは対象、操作内容、完了を判断する確認方法を含める。
6. 「計画書の推敲」に従って計画書を推敲し、計画とチェックリストをユーザーに短く提示する。重大な不明点があれば質問し、回答が必要な間は編集を進めない。計画の提示は実作業の許可とみなさない。
7. ユーザーから進捗更新を依頼された場合、確認できた完了項目だけを `- [x]` にする。新たな作業が必要なら、理由を添えて同じ計画書に項目を追加する。実施状況が不明な項目は完了扱いにせず、確認する。
8. 完了記録を依頼された場合、実際に得られた情報だけを使って、未完了項目、実施済みの確認、残課題を計画書に記録する。未確認の検証を実施済みとして記載しない。
9. 進捗や完了記録を更新した場合も、「計画書の推敲」に従って推敲する。変更した計画書の内容とチェック項目の状態を確認し、更新内容と未解決事項を簡潔に報告する。

## 計画書の推敲

- 計画書の作成・更新後、ユーザーへの提示・完了報告の前に `/yomiyasu` スキルの `SKILL.md` を読み、その手順に従って今回作成・更新した日本語を推敲する。推敲結果は同じ計画書に反映する。
- 目的、範囲、制約、完了条件、作業順序、日時、ファイルパス、チェック項目の完了状態、検証結果の事実関係を保つ。推敲に伴う説明や検査記録は計画書の本文に混ぜず、`yomiyasu` の指示に従って報告する。
- `yomiyasu` が利用できない場合は、推敲を実施したと扱わず、未実施であることと理由を報告する。

## 日時の取得方法

- 実行環境に現在時刻を返す時計ツールがあれば、それを使う。OSに依存せず、推測した時刻や会話開始時刻を使わない。
- 時計ツールがなければ、Python 3 の標準ライブラリでローカル時刻を取得する。Windows では `py -3` または `python`、macOS/Linux では `python3` を使い、次を実行する。
  `-c "from datetime import datetime; print(datetime.now().astimezone().strftime('%Y-%m-%d %H:%M'))"`
- Python 3 も使えない場合は、その環境で利用できるOS標準の日時コマンドを使う。取得できないときは日時を作らず、ユーザーに確認する。
- 取得した時刻のタイムゾーンに従い、計画書に時刻を記録する。

## 判断基準

- 計画書の場所、対象作業、または記録対象の進捗を判断できない場合だけ、最小限の質問をする。
- 既存の計画書が複数あり、対象が選べない場合は、どれを使うか確認する。
- 対象範囲や完了条件に重大な曖昧さがある場合は、推測で確定せず確認する。
- 追加項目は依頼された作業に必要なものに限定し、計画書内の既存項目との重複を避ける。

## 完了条件

- 目的、対象範囲・対象外、前提・制約、完了条件、順序立てた手順が記録されている。
- 各チェック項目が実行単位で、対象、操作、確認方法を判別できる。
- 既存の計画書を無断で上書きしていない。
- 完了状態と検証結果は、ユーザーから得た情報または実際に確認できた内容に一致している。
- 作成・更新した日本語を `/yomiyasu` で推敲し、反映している。実施できなかった場合は、その旨と理由を報告している。
