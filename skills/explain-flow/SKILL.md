# Explain Flow

選択中の関数または処理について、ソースコードの静的な追跡だけで動作の順序と結果を日本語で説明する。プログラムを実行して動作を観測せず、コードの変更ではなく理解の支援に集中する。

## 手順

1. 選択範囲から説明対象と開始点を特定する。選択がない、または対象が特定できない場合は、関数名やファイル位置など必要最小限の情報を尋ねる。
2. 対象コードと、説明に必要な呼び出し先・参照先を読み、制御フローとデータの流れを追う。対象を理解するのに必要な範囲に限って周辺コードを確認する。
3. 実行順に、処理の各段階、呼び出し、条件分岐、ループ、早期終了、例外・エラー処理を整理する。分岐ごとに条件と結果を示す。
4. 関係する変数、定数、列挙値、構造体、フラグを抽出する。それぞれの役割と、コードで確認できる初期値・設定値・処理中の値の変化を説明する。
5. 状態やデータがどのように変わるかを追い、処理の戻り値、副作用、出力、または次の待機状態を特定する。
6. 説明を日本語で、実行順が分かる構成にまとめる。該当するファイルやシンボルへのリンクを根拠として添え、コードから確認できない点は未確認として区別する。

## 判断基準

- 対象の内部処理を説明するため、呼び出し先や値の定義元を必要な分だけ辿る。無関係なリポジトリ全体の説明には広げない。
- 条件式、既定値、設定元が別ファイルにある場合は、その定義を確認してから説明する。
- 複数の経路がある場合は、各経路の条件と結果を対比する。到達不能かどうかをコードだけで判断できない場合は断定しない。
- コードから動作を確定できない場合は推測を事実として書かず、確認できた範囲と不足している根拠を示す。
- 実行時の入力や環境に依存する値は、ソースコードだけで確定できる場合に限って説明する。実行・デバッグ・テストで値を調べず、静的に確定できない値は未確認として示す。
- 説明のための依頼ではソースコードを変更しない。

## 出力

- **概要**: この処理の目的と最終的な結果。
- **実行フロー**: 起点から順に、呼び出し・分岐・ループ・エラー経路を説明。
- **主要な値と状態**: 関係する変数などの役割と、重要な値の変化。
- **未確認事項**: コードから確定できなかった点がある場合のみ記載。

各項目は対象コードへのファイルリンクやシンボル名で裏付ける。関係しない項目は省略してよい。

## 完了条件

- 対象の開始点から、戻り値・副作用・出力または待機状態までの流れを説明した。
- 重要な分岐、ループ、エラー経路と、それぞれの結果を説明した。
- 処理に関係する主要な値や状態について、役割と確認できる変化を説明した。
- 静的なコード追跡だけで説明し、実行時の事実を推測で補っていない。
- 事実と未確認事項を区別し、コードの変更を行っていない。
