# Architecture Flow HTML

## コードを調べる

1. 指定されたリポジトリを対象にする。指定がなければ、現在のリポジトリを使う。README、ビルド・依存関係の設定、主要ディレクトリを確認し、実際のコードと照合する。
2. プログラムの実行が始まる箇所、初期化、主要モジュールの責務と呼び出し関係、外部との入出力を特定する。実行の起点が複数ある場合は、用途ごとに示す。
3. 指定されたフローか、通常の利用を代表する処理を一つ選ぶ。選んだ理由を一文で示し、起点から処理の終了または次の待機状態まで実コードを追う。各段階で誰が何を実行し、どのデータを次に渡すかを確かめる。モデルやビルド構成によって経路が変わる場合は、関連する条件と共通部分を確認する。
4. 主要な説明とフローの各段階に、確認したファイルとシンボル名、または行番号を対応付ける。実行時に切り替わる処理や外部サービスの内部動作を確定できない場合は、確認できた境界と未確認の点を示す。

## HTML にまとめる

- 日本語の解説を UTF-8 の HTML ファイル一つにまとめる。ブラウザーで直接開けるように、必要な CSS はファイル内に記述し、描画に外部ライブラリやビルドを必要としない構成にする。
- 冒頭に対象リポジトリ、調査範囲、全体像を置く。本文で主要モジュール、外部との入出力、代表フロー、関連する構成差分を説明する。処理の順序は番号付きリストにし、モジュール間の関係を図にする場合は本文でも説明する。
- 根拠は対応する説明の近くに置く。ローカルファイルへのリンクは HTML の保存先を基準に相対パスを解決する。参照したコードがリモートにある場合は、確認したコミットの該当ファイルや行へのリンクを使う。リンク先を確認できない場合は、リポジトリ内のパスとシンボル名を文字で示す。コード断片は HTML として解釈されない形にエスケープする。
- 指定された場所に保存する。指定がなければ、現在の作業ディレクトリに `architecture-flow.html` を作る。既存ファイルと重なる場合は、対象リポジトリ名などを加えて別のファイル名にする。

## 出力を確認する

保存した HTML を確認し、代表フローを起点から終点までたどれること、根拠のリンク先が実在すること、未確認の点が明示されていることを確かめる。ブラウザーで確認できる場合は、狭い画面でも本文とフローの順序を読めることを確認する。回答では、保存した HTML ファイルへのリンクを渡す。
