# Architecture Flow

現在のリポジトリを調査し、アーキテクチャと通常時の代表的な動作フローを、実際のコードを根拠に日本語で説明する。

## 手順

1. README、ビルド・依存関係設定、プロジェクト構成、主要ディレクトリを確認する。READMEの説明だけで構成を確定せず、実際のコードと設定に照らす。
2. リポジトリ全体を対象に、エントリポイント、初期化処理、主要モジュールとその呼び出し関係、外部との入出力を特定する。特定のファイルや機能だけを見て全体像とみなさない。
3. 通常時の代表的な処理を1つ選び、起点から終端または次の待機状態まで、呼び出しをコード上で追跡する。各段階の責務とデータの受け渡しを確かめる。
4. 主要なモデル差分やビルド構成の違いがある場合は、それぞれを確認し、共通部分と差分を分けて整理する。
5. 調査結果を日本語でまとめる。全体構成、主要コンポーネントの責務と関係、代表フローの順序、外部入出力、重要な差分を含める。説明には該当するファイルへの相対リンクやシンボル名を付け、確認できた事実と推測・未確認事項を区別する。

## 判断基準

- エントリポイントが複数ある場合は、通常利用の起点を特定し、必要なら用途ごとに分けて説明する。
- 複数の処理フローが候補になる場合は、通常の利用者操作または主要な実行経路を代表として選び、選択理由を短く示す。
- 呼び出し先や外部動作をコードから確定できない場合は、推測で補わず、確認できた境界と不明点を記録する。
- 大きなリポジトリでは、全体構成を押さえたうえで主要経路を深く追う。細部を網羅したように見せず、調査範囲を明記する。

## 完了条件

- README、ビルド設定、プロジェクト構成を確認し、実コードと照合した。
- エントリポイント、初期化、主要モジュール間の関係、外部入出力を根拠付きで説明した。
- 代表的な通常フローを、開始点から終端または待機状態まで順に追跡した。
- 関連するモデル・ビルド差分を確認し、確認できない点を事実と混同せずに示した。
